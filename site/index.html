The launch ladder

Every command rx runs passes through four ordered rungs. Three of them consult something already written down. The fourth is the only one permitted to fail first, and the only one that writes anything back.

01 expand alias A safe zsh or fish alias body expands first. Anything depending on control flow, pipes, or eval is skipped rather than half-emulated.
02 apply mapping An exact wrapper from prefixes.toml, or one discovered from your 1Password plugins, dotenvx, or mise config.
03 run directly No wrapper at all. The common case, and the reason this rung needs no ink of its own.
04 try, then learn Each candidate_prefixes entry is tried in turn. The one that succeeds is persisted for next time, if learn_on_successful_fallback is set.

Because rung 4 may re-run a command after it already failed, fallback learning belongs to idempotent commands and auth wrappers — never to anything destructive.

What it accepts

A script qualifies by its shebang. rx installs it, derives the command name from the filename stem, and records it so rx run can find it later.

Source types are a local file, a local directory scanned recursively, or a single remote URL. A directory that matches nothing fails rather than reporting success.

Across a workspace

Three commands share the same --scan, --manifest, and --filter flags, so a workspace can be inspected or driven without naming each repo.

CommandWhat it does across every matched repo
rx status Branch, clean or dirty, ahead/behind, staged, modified, untracked, last commit.
rx graph Cargo dependency edges as a tree, JSON, or Mermaid; --who-uses and --deps for either direction.
rx fan Runs one command everywhere in parallel, with a per-repo timeout, --fail-fast, and --dry-run.
